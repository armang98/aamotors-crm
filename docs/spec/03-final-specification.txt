# 5. PAGE 1 — QUICK ADVERTISING

The homepage must provide a simple advertising message composer.

## Required Fields

- Advertising image upload
- Advertising message textarea
- Customer phone number input
- Customer search and selection
- Multiple recipient selection
- Checkbox: Include latest vehicle service history
- Send button

## Message Composition

The administrator must be able to:

1. Upload an image.
2. Write an advertising message manually.
3. Select one or multiple customers.
4. Optionally include vehicle service history.
5. Preview the final message.
6. Send the message.

## Messaging Delivery Priority

Implement this exact sequential fallback order:

1. WhatsApp Business Cloud API
2. Viber Business Messages
3. Telegram Bot
4. Viber Bot API

Do not send through all channels simultaneously.

### Fallback Rules

- Check customer eligibility for each channel.
- Check channel-specific marketing consent.
- Check provider configuration.
- Attempt the highest-priority eligible channel first.
- Stop after confirmed delivery.
- Continue to the next channel only after a conclusive failure or confirmed unavailability.
- Do not automatically fall back while a previous delivery result is ambiguous.
- Store every delivery attempt.
- Prevent duplicate messages.
- Support manual reconciliation of uncertain outcomes.

## Include Latest Vehicle Service History

When the checkbox is enabled:

1. Find the customer's vehicle.
2. If multiple vehicles exist, require explicit vehicle selection.
3. Retrieve the latest service record.
4. Append a formatted summary where the selected channel permits it.
5. Include:
   - Vehicle brand and model
   - Service date
   - Mileage
   - Oil name
   - Oil replacement type
   - Oil filter name and code
   - Cabin filter name and code
   - Air filter name and code
   - General service description
6. Omit empty fields.
7. If no service history exists, send the original advertising message.
8. Display a final message preview before sending.

For WhatsApp business-initiated marketing, use approved templates and their permitted parameters rather than arbitrary free-form content.

Never disclose vehicle service history to an unverified recipient.

# 7. PAGE 3 — REFERRAL BONUSES

Implement a referral tracking system with a fixed **10% discount**.

The discount percentage must not be editable.

## Referral Workflow

1. An existing customer invites a friend.
2. The administrator records who invited whom.
3. The invited customer completes their first qualifying paid service.
4. The referring customer receives one 10% discount entitlement.
5. The entitlement can be redeemed on one eligible future service.
6. Once redeemed, the entitlement cannot be reused.

One invited customer can generate a reward only once.

A referring customer can earn separate entitlements from different invited customers.

Do not stack multiple referral discounts on the same service order.

## Referral Fields

- Referral UUID
- Referring customer
- Invited customer
- Referral date
- Referral status
- Discount percentage: 10%
- Qualifying service order
- Reward issue date
- Reward redemption date
- Reward status
- Redeemed service order

## Referral Statuses

- PENDING
- CONFIRMED
- REWARDED
- CANCELLED

## Reward Statuses

- NOT_ISSUED
- AVAILABLE
- REDEEMED
- VOIDED

## Referral Page

Provide:

- Referring customer search
- Invited customer search
- Add referral form
- Referral history table
- Referral status management
- Available discount tracking
- Redeemed discount tracking

## Referral Analytics

Add charts showing:

- Total referrals
- Confirmed referrals
- Issued rewards
- Redeemed rewards

Provide monthly and yearly filters.

## Validation

Prevent:

- Self-referrals
- Duplicate referrals
- Duplicate reward issuance
- Repeated redemption
- Reward issuance without a qualifying paid service

Use database constraints and transactions.
