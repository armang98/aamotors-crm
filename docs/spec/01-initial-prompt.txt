# PAGE 3 — REFERRAL BONUSES

Implement a simple referral program.

## Fixed Bonus Rule

**The referral reward is always a 10% discount.**

Do not implement configurable bonus amounts.

Do not use fixed AMD rewards.

Do not allow employees to modify the percentage.

The 10% value must be defined as a business rule constant and enforced by the backend.

## Referral Workflow

1. An existing customer recommends the auto service to a friend.
2. An employee opens the Referral Bonuses page.
3. The employee selects the existing customer.
4. The employee selects or creates the invited customer.
5. The system creates a referral record.
6. The invited customer completes their first qualifying paid service.
7. The referring customer receives one 10% discount entitlement.
8. The referring customer can redeem that entitlement on one eligible future service.
9. After redemption, that entitlement cannot be reused.

Each invited customer can qualify for a referral reward only once.

A referring customer may earn separate one-time 10% discount entitlements for different eligible invited customers, but the same invited customer cannot generate another reward.

Do not stack multiple referral discounts on a single service order.

- Referral UUID
- Referring customer ID

- Referral status
- Fixed discount percentage: 10%
- Qualifying service order ID
- Reward issued date
- Reward redemption date
- Reward status
- Redeemed service order ID

## Referral Statuses

## Reward Statuses

## Fraud and Duplicate Prevention

- Prevent self-referrals.

- Validate qualifying paid service records.
- Use database constraints and transactions.
- Record an audit trail for reward issuance and redemption.
